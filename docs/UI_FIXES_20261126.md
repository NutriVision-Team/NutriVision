# UI fixes, 26 Nov 2026

Defects found in a review of all screens (360, 390, 800x1280, 1280x800, 1440x900; Arabic and English; dark and light) and what changed.

## Fixed
- **Responsive frame:** tablet and desktop widths now use a proper shell instead of the stretched phone layout. Covered by widget tests at the sizes above.
- **Home hero card:** layout corrected on wide and narrow screens.
- **Account tab:** content no longer breaks in the tablet shell.
- **Favorites:** below 380 px wide the list layout is used. This removed a 3 to 5 px overflow at 360.
- **System back:** `lib/app/back_guard.dart`. Back pops a page when one exists. A signed-in page with nothing to pop goes to Home. On Home a second press within 2 seconds exits. The setup wizard steps back one step. Register goes to login. Disabled on web.
- **Effects:** orange hover, blue wavy press, applied through the theme and `SufraControlFeedback` on custom pills, chips, text links and recipe meal-type pills. `overlay: true` mode keeps shadows from being clipped. Respects reduced motion.
- `flutter_animate` was removed (its pending timers fail widget tests); plain animation widgets are used.

- **Google sign-in on Android/iOS:** the login screen always handed the web dialog callback to the gateway, which then took the web path, got no identity and reported "Google sign-in canceled" without opening the native account picker. The callback is now passed only on web, so Android/iOS call the native picker. Web is unchanged.
- **Sufra Premium entry:** the Premium screen (design screen 31) existed at `/premium` but nothing linked to it. The Profile (حسابي) tab now has a "Sufra Premium" card that opens it, with system back returning to the profile. The screen stays display-only: no purchase, trial or price.
- **Log out:** the Profile (حسابي) tab has a "Log out" card at the bottom with a confirm dialog (cancel keeps the session). Confirming runs the existing session sign-out (push token unlink, reminders cleanup, Firebase sign-out) and now also clears the device Google account on Android/iOS so the next Google sign-in shows the account picker. The router sends a signed-out session to the login screen, which links to register.
- **Forgot password:** the emailed code is entered in six separate boxes (`otp_code_field.dart`): auto-advance, backspace goes back, pasting a full code into any box fills all, Arabic-Indic digits convert, digits stay left to right in Arabic. Tested with a mock reset service (the pasted code is what is sent).

## Sign-in security review
- Passwords, tokens and Google credentials are never stored by the app. Firebase Auth keeps its own session natively. App preferences hold only UI and local data (theme, language, reminders, push installation id and owner uid, caches, local ledger queue).
- The app has no Dio. Network calls use `http` over HTTPS to the Cloudflare Workers and Firebase SDKs. Android cleartext traffic is now explicitly off, and the reset service refuses a non-HTTPS endpoint.
- Android auto-backup is turned off so local data (uid, reminder settings) is not copied to cloud backups.
- Logs: the only `debugPrint` lines are fixed status texts with no emails, codes, tokens or uids.
- Email/password sign-in and register now time out after 30 seconds with the normal network error instead of spinning forever. The reset-code calls already time out at 20 seconds.
- Already in place: double-tap protection on sign-in, register and Google (busy flag), Google duplicate-request guard, mapped messages for too many attempts, network failure, wrong credentials, weak password and invalid email, email and password validation on the forms.
- No automatic retry of sign-in or register by design (a retried create could duplicate or lock an account). Rate limiting is Firebase's and the Worker's own (`rate_limited` message).
